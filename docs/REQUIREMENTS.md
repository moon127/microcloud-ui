# microcloud-ui — Requirements

Status: **draft for sign-off**. Each requirement has an ID and a tier:
**MVP** (first usable release), **P2** (after MVP), **Later** (nice to have).
Change tiers here; record the reason in `agents.md`.

## 1. What the stock UI at `https://<member>:8443/ui` actually is

Findings from reading `canonical/lxd-ui` source (main @ c21a4e7, 2026-11-05)
and the LXD REST spec (`docs/lxd-api-surface.md`):

- **A static React SPA served by the LXD daemon itself** at `/ui`. It has no
  server-side component of its own: every action is a plain call to the same
  LXD REST API (`/1.0/...`) on the same origin, plus websockets for
  exec/console and `/1.0/events?type=operation,lifecycle&all-projects=true`
  for live updates. **So anything the UI can do, our backend can do with a
  trusted client certificate.**
- **Auth in the browser:** a TLS client cert imported into the browser
  (generated by the UI as a password-protected `.pfx`, trusted via
  `lxc config trust add` or a bearer-token flow) or OIDC. We replace this
  with our backend holding the cert (D4).
- **Its "metrics" are live only.** It does call `/1.0/metrics?target=<member>`
  (via the browser cert) every 15s and parses it client-side, but keeps just
  the **last 6 samples (~90s) in browser memory**: instance CPU, memory,
  root filesystem; member CPU/memory. Nothing survives a page reload, and
  there's no disk I/O, network, storage-pool, Ceph or OVN history. That is
  the gap we fill.
- **About 50 LXD endpoints are used.** The full LXD API is 126 path templates
  (`docs/lxd-api-surface.md`). Endpoints the stock UI does *not* use but we
  want for monitoring: `/1.0/networks/{}/state` (interface counters),
  `/1.0/storage-pools/{}/resources` (capacity), `/1.0/projects/{}/state`
  (quota usage), `/1.0/network-acls/{}/log`, `/1.0/instances/{}/backups`.
- LXD-UI is GPL-3.0. **We do not copy its code**; we only use it as a
  behavioural reference. (Licence for this repo: see open question Q3.)

## 2. Functional requirements: management (parity with /ui)

Common to all objects: list with search/filter/sort; detail view; create,
edit and delete with a form **and** a raw YAML editor; project-aware; clustered
`target` selection where the API supports it; long-running actions shown as
operations with progress and cancel.

## 3. Functional requirements: monitoring (the gap)

| ID | Requirement | Tier |
|---|---|---|
| MO-1 | Scrape `/1.0/metrics` from **every** cluster member (members discovered automatically) every 15s (configurable, minimum 10s), using a `--type=metrics` cert or the main client cert | MVP |
| MO-2 | Persist history in SQLite with rollups (raw 24h, 1m 14d, 1h 1y; configurable) | MVP |
| MO-3 | Instance graphs: CPU (% of effective CPUs), memory (used/RSS/cache/swap), OOM kills, disk read/write bytes & IOPS per device, filesystem used/free per mount, network rx/tx bytes, packets, errors, drops per NIC, process count; time ranges 15m to 1y | MVP |
| MO-4 | Member graphs: aggregated instance CPU/memory/net/disk; host load and memory from `/cluster/members/{}/state`; LXD daemon health (API request rates and errors, ongoing ops, warnings, goroutines, uptime) | MVP |
| MO-5 | Top-N tables (instances by CPU, memory, net, disk I/O) cluster-wide and per project/member | MVP |
| MO-6 | Storage pool capacity & inode usage history per member (`/storage-pools/{}/resources`); volume usage (`/volumes/.../state`) | MVP |
| MO-7 | Ceph dashboard from the ceph-mgr `prometheus` module (`:9283` on each mgr host, active mgr answers): health, OSD up/in, PG states, raw & per-pool capacity, client IOPS/throughput, OSD latency | MVP |
| MO-8 | Network graphs: per-network interface counters (`/networks/{}/state`), traffic aggregated from instance NICs per network | MVP |
| MO-9 | OVN view from LXD API: OVN networks with uplink, router addresses, forwards/LBs/peers/ACLs, allocations; health summary | MVP |
| MO-10 | Project quota usage over time (`/projects/{}/state`) | P2 |
| MO-11 | Deep OVN/OVS internals (NB/SB DB status, chassis, port bindings, logical flows count, datapath stats) through an optional read-only node agent or ovn-exporter | Later |
| MO-12 | Host OS metrics via `node_exporter`, if present | P2 |
| MO-13 | Threshold alerts (pool > X%, OOM kills, member offline, Ceph not HEALTH_OK) shown in UI + webhook | P2 |
| MO-14 | **Evaluate alternative metric stores** (Prometheus, VictoriaMetrics, others) behind the existing `MetricStore` interface; write up and pick | P2 |
| MO-15 | CSV/JSON export of any graph's data | P2 |

## 5. Non-functional

| ID | Requirement |
|---|---|
| NF-1 | Python ≥ 3.10 backend; tested on 3.10 and 3.12 |
| NF-2 | ≥ 90% line+branch coverage for backend and frontend; tests in the same commit as features |
| NF-3 | Always verify LXD's TLS certificate (pinned `server.crt`, optional `server_name`); never disable verification |
| NF-4 | Scale target: up to 10 members, 1,000 instances, 15s scrape, < 1 GB SQLite/year at default rollups |
| NF-5 | LXD compatibility: the LXD version MicroCloud ships (5.21 LTS / 6.x, to confirm); degrade gracefully |
| NF-6 | Deploy as Python package + systemd unit and as an OCI container image |
| NF-7 | Manual dev run on macOS documented (venv, backend with reload, Vite dev server) |
| NF-8 | UI usable on desktop and tablet widths; keyboard accessible; light/dark |

## 6. Out of scope (for now)
MicroCloud bootstrap/`microcloud add` flows, MicroCeph/MicroOVN
installation or reconfiguration, enterprise storage drivers, multi-cluster
management.
